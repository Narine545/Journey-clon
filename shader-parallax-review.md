# Пигмент, глиттер и SDF: изменения

## Проверка в игре

- `K`: исходный глиттер / усиление на гребнях. Максимальное усиление теперь +65% вместо +45.5%, без увеличения количества искр.
- `P`: внутренний параллакс пигмента вкл/выкл. Смотреть на жилки внутри пятен при прохождении волн; внешний контур остаётся на поверхности.
- Параллакс включён при старте, глубина 0.55 м. Это виртуальные внутренние слои, не настоящая толщина геометрии и не преломление изображения сцены.

## Local refract / single face parallax

Страница https://godotshaders.com/shader/local-refract-single-face-parallax/ описывает смещение внутренней плоскости по направлению взгляда и нормали поверхности. Извлечённый блок исходного кода пуст: побайтового переноса не было.

Собственная реализация в `resource_slick.gdshader`: направление взгляда с отдельной веткой для ортографии, нормаль из общего спектра волн, преломлённый луч (IOR 1.33), смещение двух процедурных внутренних слоёв с разной глубиной. Маска края пятна остаётся поверхностной. Нет screen texture, тяжёлого реймарчинга или новой normal-map текстуры. Добавлены семь спектральных компонент на фрагмент пятна и четыре hash-выборки для плавных внутренних карманов; стоимость на GPU не измерена.

## Fullscreen SDF raymarching

Ссылка https://godotshaders.com/shader/fullscreen-sdf-raymarching-with-smooth-csg-and-depth/ соответствует `sand_sea_sdf.gdshader`, используемому через `SandFish` в старой рыболовной сцене (`scripts/main.gd`). В лодочной сцене пятна используют отдельный `resource_slick.gdshader`: их smooth-union двумерен, это НЕ полноэкранный 3D raymarcher.

Подтверждённые исправления:

1. Прежний raymarcher начинал все лучи в позиции камеры, направление вычислял через far point. Это перспективная конструкция, неверная для ортографической камеры.
2. Теперь начало — восстановленная near point для каждого пикселя, направление — far minus near. Параллельность ортографических лучей сохраняется.
3. Ограничение по depth texture измеряется вдоль того же луча от near point, а не длиной view-space позиции.
4. Для антиалиасинга размер ортографического пикселя постоянен, не умножается на расстояние.

Сохранены reversed-Z near=1/far=0, depth write через PROJECTION_MATRIX, smooth CSG и ограничение плоскостью воды. Это целевой аудит реконструкции лучей, НЕ полная сертификация всех SDF-примитивов и окклюзии прозрачной воды. Средняя плоскость воды остаётся приближением, а не точной волновой поверхностью.

## Проверки

`python3 tests/check_projection_rays.py`: параллельные ортографические лучи, перспективные лучи, расстояние до глубины сцены, статические проверки шейдеров.

`python3 tests/check_wave_spectrum.py`: CPU/GPU параметры спектра и аналитический градиент.

GDScript проверен gdparse. Эти проверки НЕ компилируют GDShader. Godot render/visual CI намеренно не запускался; визуальное качество и производительность требуют проверки в игре.

## Коррекция после проверки пользователем

Первая версия оставляла sin-полосы доминирующим рисунком, а смещение этих полос не дало пользователю заметного ощущения глубины. Полосатый рисунок удалён: вместо него плавный domain-warped noise, два слоя облаков пигмента, отдельный внутренний контур ядра. Убраны скачущий дискретный шум на краю и пульсирующая яркая обводка. `P` отключает смещение слоёв, но не возвращает старые полосы. Параллакс остаётся имитацией внутренней глубины; визуально и на GPU новая версия не проверена. `tests/check_slick_material.py` — только статические регрессионные проверки.

## Перенос формулы из предоставленного исходника local-refract

После получения кода заменён физический `refract()` на single-face parallax `view_tangent.xy / view_tangent.z * depth`. Поверхностная нормаль теперь получает плавный процедурный normal-map слой, а не только малые наклоны больших волн. Касательный базис ортогонализируется после изменения нормали; все dot/cross выполняются в world space. Это исправляет смешение world-space NORMAL и view-space TANGENT/BINORMAL в предоставленном фрагменте.

Для PlaneMesh XZ рисунок задан локальными метрами, поэтому вместо деления UV на mesh_dimensions world offset переводится обратной MODEL_MATRIX. Нормализованные UV и текстуры из примера не копировались: ассеты normal_texture/projection_texture не предоставлены, их заменяют процедурные поля. `refract_strength=0.75`, `normal_scale=1.6`, depth=0.55; размер смещения ограничен 1.25 м против выбросов на скользящих углах. На `P` depth становится нулём, оба слоя перестают проецироваться; поверхностная линза остаётся для блика.

Численный тест касательного базиса проверяет ортогональность, зависимость смещения от наклона, нулевую глубину и предел смещения. Это НЕ визуальная проверка и НЕ компиляция GDShader. Новый результат ещё требует проверки пользователем.

## Ночная видимость пигмента

Начиная с night_factor=0.40 дневная видимость плавно заменяется маской носового прожектора; при 0.78 пятна вне луча полностью прозрачны, включая emission. Маска использует фактические global position, -basis.z, spot_angle, spot_range и visible/energy прожектора, обновляемые каждый кадр; форсаж и H учитываются. Геометрия пятна и сбор ресурсов не меняются.

Это аналитическая маска конуса, а не физическое освещение материала. Сохраняется обычный depth test против корпуса/берега со стороны камеры, но тени препятствий со стороны прожектора маска не рассчитывает. Если препятствие находится между прожектором и пятном, не закрывая пятно от камеры, оно всё ещё может проявиться. Для такой окклюзии требуется отдельная проверка препятствий или интеграция с теневой картой, здесь не реализованная.

Проверка: `python3 tests/check_slick_visibility.py`; в игре 5 до ночи, поворот лодки, H выключить/включить. Днём H не должен скрывать пятна. Визуальный CI не запускался.
