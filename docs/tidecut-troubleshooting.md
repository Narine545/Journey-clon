# TIDECUT UI · если игра падает при запуске

Короткая памятка: что смотреть, когда проект закрывается сразу после F5 и в
консоли пусто. Молчаливый выход — это почти всегда не ошибка GDScript (её Godot
печатает), а смерть процесса: драйвер, OOM, kill или устаревший кэш импорта.

## 1. Лог всё равно пишется

Godot пишет лог даже при падении процесса:

- Windows: `%APPDATA%\Godot\app_userdata\To The Light\logs\godot.log`
- Linux: `~/.local/share/godot/app_userdata/To The Light/logs/godot.log`
- macOS: `~/Library/Application Support/Godot/app_userdata/To The Light/logs/godot.log`

Загрузка `BoatWorld` теперь оставляет хлебные крошки вида

```
[BOOT] старт · 128 МБ
[BOOT] мир собран · 402 МБ
[BOOT] HUD рейда · 455 МБ
[BOOT] меню · 470 МБ
[BOOT] постобработка · 512 МБ
[BOOT] готово · 540 МБ
[BOOT] афиша открыта · 541 МБ
```

Последняя напечатанная строка — шаг, на котором процесс умер. Это сразу делит
причины на «мир/3D», «интерфейс», «постобработка» и «после загрузки».

## 2. Устаревший кэш импорта

После большой переделки UI (новые шрифты, шейдеры, десятки `.tscn`) старый
каталог `.godot/` иногда ломает запуск молча.

1. Закрыть редактор.
2. Удалить `.godot/` в корне проекта (это кэш, он пересоздаётся).
3. Открыть проект и дождаться окончания импорта.

CI каждый раз импортирует проект с нуля — там этой проблемы нет.

## 3. Запуск из терминала

Из редактора консоль может закрыться вместе с процессом. Надёжнее так:

```
godot --path /путь/к/Journey-clon --verbose > boot.log 2>&1
```

`--verbose` печатает инициализацию драйвера и загрузку ресурсов — по последним
строкам видно, упал ли Vulkan при создании swapchain или уже наш код.

Если хочется проверить гипотезу «дело в Vulkan-драйвере»:

```
godot --path . --rendering-method gl_compatibility
```

Игра задумана под Forward+ (объёмный туман, glow), но факт падения в
Compatibility-режиме отделяет драйвер от проекта.

## 4. Что уже проверено автоматически

`validate.yml` → job `ui` → шаг **Boot the real game**: та же сцена
`res://scenes/boat_main.tscn`, что открывает игрок, запускается с настоящим
рендером (xvfb + lavapipe, Godot 4.7.2), снимает кадр
`shots/tide_07_boot.png` и валит сборку, если в логе есть

```
SCRIPT ERROR | SHADER ERROR | Parse Error | Segmentation fault | handle_crash | crash_handler
```

Лог лежит в `.ci-logs/boat-boot.log`. То есть «проект не стартует» на чистой
машине ловится в CI; если CI зелёный, а у вас падает — разница в драйвере,
версии движка или локальном кэше импорта.
